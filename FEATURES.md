# Winlator Mali+ Feature and Upstream Port Guide

This document inventories the Winlator Mali+ changes layered onto upstream Winlator Mali and gives a future agent a checklist for rebasing them onto a newer upstream source. It is not a substitute for inspecting the current implementation: use it to locate the relevant code, then verify behavior and APIs in both revisions before porting.

## Integration baseline

- The local integration branch is `bionic-mali-1.2`. Its current committed baseline is merge commit `acff21f20794e085ce3d0f3f27876650e9c01677`, with local parent `4ef849eb6282db26cbd4c476f93fc32652fb7ccb` and upstream Winlator Mali 1.2.1 parent `428bd945be92c2063fe01daf770fa7310126e1b2`.
- The original Mali+ integration was based on upstream Winlator Mali 1.2 commit `e34f1e87f875fa143bf5bca6bd37fc2f781528d9` and integration commit `ceb730481bf3f7f146c19947bd161445a4a721ad`; these are historical references, not the current rebase base.
- The current working tree may also contain uncommitted follow-up changes. Check `git status` and review the complete diff before using the committed merge as the only source of truth.
- Keep the upstream native EGL/Gladio renderer and ZeroFG path. Vulkan host rendering is an additional choice, not a replacement for those defaults.
- The original Mali+ source branch is `bionic-mali-1.0`; use it as a historical reference when a change is not documented here. Do not merge old files wholesale over newer upstream files: the renderer and UI APIs have changed.
- No GitHub push is implied by this guide. Keep future integration local until explicitly asked otherwise.

## Mali+ additions and adaptations

### Optional Vulkan host renderer

- Adds Vulkan as an optional host/display renderer, selectable in container settings and shortcut settings. OpenGL remains the safe/default path.
- Persists renderer choice and related settings across container and shortcut configuration, with shortcut values falling back to their container.
- Adapts the Vulkan Java renderer to upstream XServer, `Drawable`, and `GPUImage` APIs, including AHardwareBuffer access and renderer lifecycle/event routing.
- Provides Vulkan-specific configuration, including color order, present mode, driver selection, post-processing controls, scaling, and display sizing/alignment where supported.
- Keeps the HUD renderer label consistent with the selected backend and avoids reporting EGL/GL values as Vulkan. Vulkan initialization failure reports the failure and falls back to OpenGL.
- Main implementation: `app/src/main/java/com/winlator/cmod/renderer/vulkan/`, `XServerDisplayActivity.java`, `widget/XServerView.java`, `container/Container.java`, and the container/shortcut settings dialogs.
- Native build integration: `app/src/main/cpp/CMakeLists.txt` and `app/src/main/cpp/winlator/`.

### Vulkan Native Rendering and direct scanout

- Adds a Vulkan Native Rendering option backed by Android SurfaceControl/AHardwareBuffer scanout.
- Selects a suitable large game drawable for direct scanout while continuing to composite other windows through Vulkan.
- Avoids switching the Vulkan compositor to its scanout black-frame path until a game buffer has actually been delivered; otherwise it keeps rendering through the compositor. This is a safeguard against a black screen when scanout has no game frame yet.
- Relevant code: `renderer/vulkan/VulkanRenderer.java`, `cpp/winlator/VulkanRendererContext.cpp`, and `cpp/scanout/ScanoutContext.cpp`.
- Runtime behavior depends on Android SurfaceControl support, the device, and the game/driver. It must be tested on-device after every renderer port.

### Vulkan frame generation, while preserving ZeroFG

- Adds Vulkan-native LSFG and Win-FG engine selection, enable/multiplier/tuning settings, and runtime application through Java/JNI/native renderer paths.
- Stores frame-generation configuration with container/shortcut settings. LSFG availability is gated by the required imported Lossless DLL/cache; Win-FG remains an available native option where supported.
- Routes Vulkan generation statistics to the HUD and prevents EGL renderer detection from mislabeling a Vulkan session.
- Keeps upstream ZeroFG and its EGL path intact. Do not remove ZeroFG or the upstream `zerofg` native target when porting Vulkan code.
- Frame generation has native processing/generation paths, but an enabled UI setting is not proof that generation is active on a device. Capability checks, engine initialization, composition, and scanout mode can prevent frames from being generated. Confirm with runtime telemetry/logs, not the checkbox alone.
- Relevant code: `contentdialog/GraphicsEnhancementsDialog.java`, `widget/WinlatorHUD.java`, `XServerDisplayActivity.java`, `renderer/vulkan/VulkanRenderer.java`, `cpp/winlator/VulkanRendererContext.cpp`, and `cpp/winlator/vulkan_jni.cpp`.

### Bannerlator wrapper catalog and selection

- Adds an online Bannerlator wrapper catalog, installed-wrapper discovery, download/update, checksum and archive validation, and local cache under the app's private `files/graphics_driver/` directory.
- Filters the known unusable BCn downloads (`bannerlator-bcn-leegao`, `bannerlator-compat-bcn`, and `wmali-bcn-fcharan`) from catalog results. This only hides them from the downloadable catalog; it does not remove files users already installed.
- The built-in wrapper is displayed as **Apex-Wrapper** while retaining the runtime identifier expected by the built-in wrapper.
- Installed catalog wrappers appear in the main Graphics Driver dropdown and shortcut settings. Their IDs are persisted so reopening settings does not silently revert the selection.
- Allows importing a local `.tzst` wrapper from Android's document picker. The archive is size-limited, validated as Zstandard/TAR, checked for unsafe paths and links, and must contain `usr/lib/libvulkan_wrapper.so`; duplicate and bundled-driver names are rejected with an English error suggesting a unique filename. Imported wrappers appear in Manage Graphics Drivers and the container/shortcut Graphics Wrapper menus.
- The local-import button stays separate and visible above the catalog section. The Bannerlator catalog dropdown starts collapsed; its description sits immediately above the toggle and only the catalog contents/status are collapsed.
- The bundled and imported driver rows share the parent vertical scroll container rather than nesting a RecyclerView inside the page ScrollView, so the complete graphics-driver list remains reachable on touch and controller-sized screens.
- At launch, the selected installed archive is extracted into the container; missing selections use the explicit built-in fallback rather than an invalid archive path.
- Catalog metadata is sourced from `The412Banner/winlator-contents`; binary wrapper archives are downloaded on demand instead of bundled into the APK.
- Relevant code: `contents/WrapperCatalogManager.java`, `ManageGraphicsDriversFragment.java`, `ContainerDetailFragment.java`, `contentdialog/GraphicsDriverConfigDialog.java`, `contentdialog/ShortcutSettingsDialog.java`, `container/Container.java`, and `XServerDisplayActivity.java`.

### Live PanVK release catalog and Adrenotools import

- Adds a **Browse & Download PanVK Driver** action to the Adrenotools GPU Drivers page. Each refresh paginates through the GitHub Releases API until all releases are checked, so older catalog entries do not hide newer or previously missed release packages. It does not silently poll in the background.
- Sources: [`zenithblue-oss/panvk-kbase-android`](https://github.com/zenithblue-oss/panvk-kbase-android/releases), [`GunaCharanTeja/panvk-kbase-android`](https://github.com/GunaCharanTeja/panvk-kbase-android/releases), [`FristOneRR/FristOneRR-Panvk-Driver`](https://github.com/FristOneRR/FristOneRR-Panvk-Driver/releases), [`Noysz/panvk-g99-jm`](https://github.com/Noysz/panvk-g99-jm/releases), and Faux123's [`ACE`](https://github.com/faux123/panvk-faux123-driver-ace/releases), [`RP4 Pro`](https://github.com/faux123/panvk-faux123-driver-rp4pro/releases), [`RG556`](https://github.com/faux123/panvk-faux123-driver-rg556/releases), and [`Pixel 7`](https://github.com/faux123/panvk-faux123-driver-pixel7/releases) builds.
- Offers only repo-specific ZIP candidates: `*-adrenotools.zip` for the first two repositories, `PanVK-*.zip` (including current `PanVK-FristOneRR-V.*` packages) for FristOneRR, `FourFectVK-G57-*.zip` for Noysz, and `panvk_faux123_*.zip` for Faux123's device-specific repositories. README/checksum files, X11/emulator/app-specific builds, raw `.so`, and unrelated ZIPs are excluded; the existing Adrenotools metadata/library checks still decide whether a candidate can import.
- Sorts all matching packages globally by release publication date, newest first (independent of author), and shows each repository owner with the exact release package, a short release-note description, tag/type/date, ZIP size, repository, and author-reported device/GPU compatibility. Compatibility notes are not a guarantee for all devices.
- Download is user-initiated and imports directly into the existing Adrenotools driver store. The download checks HTTPS/GitHub host, expected byte size, configured maximum size, and the release SHA-256 when GitHub supplies a digest.
- Adrenotools ZIP import requires root `meta.json`, valid `name`, `libraryName`, and `driverVersion` values, and the referenced library file. Extraction rejects unsafe paths, caps expanded size/file count, and refuses to overwrite an already installed driver name.
- The screen and confirmation warn that PanVK is experimental and may be less smooth/stable than the built-in System driver. Return to System if the custom driver causes issues. Driver choice and actual compatibility must be tested on the target Mali GPU/kernel.
- The latest ZIP from each listed repository was checked during implementation for the Adrenotools metadata/library layout. That is a package-format check, not an on-device compatibility test.
- Relevant code: `contents/PanvkReleaseManager.java`, `contents/AdrenotoolsManager.java`, `AdrenotoolsFragment.java`, `res/layout/adrenotools_fragment.xml`, `res/layout/panvk_release_list_item.xml`, and `res/values/strings.xml`.

### Game library, artwork, and executable shortcuts

- Requests cloud cover-art discovery for shortcuts that do not already have primary artwork, using the existing SteamGridDB/artwork path and preserving local/custom art as the preferred source.
- Adds a direct **Add game (.exe)** picker action to the Shortcuts screen. The user selects a Windows executable and target container; the app copies the executable under the container's `Program Files`, creates a `.desktop` entry, requests icon extraction, and refreshes the library.
- Adds safeguards for shortcut cover art: local picker completion updates only the chosen shortcut rather than reloading the library; local selection is persisted while the picker is open; writes use a same-directory temporary file and atomic replacement where supported; a shared per-art-file version rejects stale background decodes and older asynchronous downloads; current bitmap state is synchronized to matching live adapter items; and default/cloud artwork uses a guarded save path. Gallery images are decoded with a 1600px maximum dimension. The user later reported the current app stable overall, but did not provide a separate cover-art regression matrix; retain the targeted checks below when porting or changing this path.
- Shortcut cards load persisted artwork files through Glide with a signature incorporating path, timestamp, file size, and shared cover-art version; after a local cover change, all visible cards are rebound without reconstructing the shortcut library. Preserve disk-backed reload behavior so artwork recovers when in-memory bitmaps are evicted.
- Preserve the explicit cover-art search/selection flow and do not replace custom/local art with a default download.
- **Cover-art verification required:** test repeated local and downloaded selections, picker cancellation/failure, delayed default downloads, simultaneous `Shortcut` instances, list refresh/rebind, duplicate shortcut names, and corrupt/unreadable files. Confirm that stale loads/downloads cannot replace the newest selection and that one shortcut's update does not clear another card.
- Uses full-bleed, center-cropped artwork as the background of both portrait and landscape game cards. Game name, container/build subtitle, and version sit over a darker bottom gradient overlay that follows the card's rounded outline; do not reintroduce a separate square metadata panel or change the established card dimensions.
- Improves shortcut carousel layout and selection behavior across portrait/landscape, applies eased carousel blur and subtle card elevation, avoids a RecyclerView item-animation recycling crash, and centers the Shortcut Details heading. Landscape card height and vertical padding are constrained by the measured carousel viewport so card titles and the shortcut-details panel remain visible rather than being clipped at the top/bottom.
- Keeps portrait shortcut-card width and artwork height independent of carousel height: portrait artwork uses a fixed 263dp height so orientation/measurement changes cannot make cover art zoom or crop differently when returning from landscape.
- Shows selected-game configuration details (DX wrapper, renderer/frame generation, Vulkan wrapper, FEXCore/Box64 versions and presets where populated). Keeps game launch bound to the explicit play action; selecting/browsing a card should not launch it.
- The portrait **Shortcut Details** panel keeps its established two-column layout. Detail text wraps instead of being clipped with an ellipsis, and the panel surface is applied from the selected theme at view creation and when returning to the screen. The heading label is `--Shortcut Details--`; landscape retains its own layout. When orientation changes, the carousel clears stale recycled holders/effects and Glide cover requests are explicitly transformed to the current card dimensions, preventing portrait art from reusing a landscape-sized crop.
- Removes the obsolete “Share with Community” shortcut-popup action.
- Refreshes the container manager when returning to the Shortcuts screen so a container created moments earlier is immediately offered by Add Game and container-selection flows.
- Relevant code: `ShortcutsFragment.java`, `container/Shortcut.java`, `FileManagerFragment.java`, `core/CoverArtManager.java`, `res/layout/shortcuts_fragment.xml`, `res/layout-land/shortcuts_fragment.xml`, `res/layout/shortcut_list_item.xml`, and `res/menu/shortcuts_menu.xml`.

### Steam account, library, installation, and shortcuts

- Adds a Steam entry in the navigation drawer with username/password + Steam Guard and QR sign-in through JavaSteam. Passwords are not persisted; the refresh token is encrypted with AES-GCM using an Android Keystore key.
- Loads account licenses and PICS metadata for owned games, persists the library in a local SQLite database, and installs Windows depots with the JavaSteam DepotDownloader. The shared app-private library is `files/imagefs/steam_games/`.
- The Steam screen includes a native Storefront API UI (new releases, current promotions, free-to-play games, and search), plus bottom navigation for Library, Friends, Profile, Downloads, and Achievements/Badges. Prices use the device locale's country when available. Paid games not owned by the account are marked **Not owned**; free games can be added through Steam's free-license request and are refreshed into the account library. Store search keeps its home control on a separate row.
- The Store presents up to three current promotions in a swipeable, snap-to-slide banner with position indicators. The Steam screen reuses the purple animated PlayStation wave background from the main Winlator screen and pauses its animation when it is not in the foreground. When Enhanced Liquid Glass is enabled, only that background receives the blur effect; Steam panels keep their regular translucent surfaces and sharp text.
- Steam profile avatar and banner requests use appropriately sized images, high request priority, and Glide's disk cache; unchanged images are not re-requested during routine profile refreshes. Avatar URLs use Steam's current Fastly CDN host and try the standard, Akamai, and Cloudflare hosts as fallbacks before showing the account-initial fallback.
- Library includes search and **All games / Installed / Not installed** filters; non-game products are excluded from the account library view. Profile uses the account persona name, SteamID64, avatar hash resolved through Steam's avatar CDN, presence, current game, a current-game hero banner when available, and an expandable synced game list. Steam's client session does not provide total playtime; the profile links to the official Steam game-details page for that information.
- Achievements are requested from Steam's authenticated user-stats session per selected library game. Public profile badges are fetched and displayed as native cards in the same Steam screen; private profiles or Steam requests that return no badge markup show an explicit error.
- Steam News is fetched from Steam's RSS feed and rendered in native Android views; article taps open an in-app native detail view with a back-to-list action rather than launching an external browser or embedding a WebView. Exact duplicate URLs are discarded, then articles with the same normalized title are grouped into one list card. The group retains every distinct article URL, date, and body in its detail view, so recurring updates (for example, repeated Team Fortress 2 update titles) are not silently discarded. The feed can still contain only a limited set of recent items; the app does not manufacture additional stories.
- Badge loading is independent of the optional Achievements/Badges page's status `TextView`: profile refreshes may request badges before that page exists. Keep badge-summary updates null/lifecycle-safe and keep profile badge/level refreshes guarded so a missing view cannot crash Steam event handling.
- Download progress shows Steam-reported transferred bytes only, labeled as compressed transfer data and explicitly not as installed size. The progress bar and percentage use JavaSteam's actual current-depot callback (`sizeDownloaded / manifest file bytes`), so the label must say **Current depot** rather than imply a whole-game percentage. Once installation completes, the app measures actual regular-file bytes on disk and stores that installed size separately from depot metadata. Shortcut settings expose only the four tabs with actual settings panels; do not add a dangling Steam tab. A four-minute no-activity watchdog marks stalled downloads as failed so they can be retried. The downloader library has no native pause API, so resume starts a new downloader against the same install folder and may reuse already completed files. Installed games can be removed from the device without removing their Steam account license. The app verifies the registered Bouncy Castle provider exposes SHA-1 before initializing JavaSteam.
- Download Pause/Resume and Cancel are distinct actions. Clearing Winlator from Recents pauses active depot tasks, removes the foreground notification, and disconnects Steam instead of treating task removal as cancellation. Paused task metadata is retained in-process; do not claim recovery after Android kills the app process unless persistent download-task restoration is implemented and verified.
- Adds a root-only gaming performance profile in Settings > Performance and the in-game Performance dialog. After the root manager explicitly grants `su`, the menu discovers CPU policies, GPU devfreq governors (including common Mali/KGSL/Adreno/PowerVR nodes), and block-device I/O schedulers from the running kernel rather than assuming a specific chipset. Available controls are device-dependent; selections are applied at game start, previous values are restored on pause/exit, and a recovery record is retried at the next app launch. GPU frequency offset is shown as disabled because no portable, verified writable kernel control exists across devices.
- Settings > Performance includes an expandable device-information card (kernel, device/model, SoC, app/Android versions, fingerprint, SELinux state, and ABI) plus the existing non-root Android game-mode, guest thread-priority, big-core affinity, sustained-performance, and supported Samsung boost options. System/kernel support and observable benefit vary by device; avoid promising a universal FPS increase.
- Adds a Friends page with per-friend chat. Incoming Steam messages generate Android notifications with quick reply and a temporary, non-interactive in-game overlay; replying while in-game uses the Android notification shade/action, while the in-game overlay is display-only. The Friends page links to the Android notification permission/channel settings. Notification visibility depends on OS permission and the user's channel settings.
- Uses the supplied Steam logo as the Steam entry icon in the navigation drawer, applied programmatically after drawer tint styling. About credits identify Valve's Steam mark and link the Steam integration to JavaSteam, and credit the Bannerlator wrapper catalog source.
- Returning to the Steam screen shows a full-blur reconnect/verification popup with a network recovery hint and retry action. A healthy existing connection is briefly verified rather than disconnected, preserving active downloads. The sign-in prompt is shown only when the account is not signed in.
- The Steam username/password fields use the active theme's foreground and hint colors, including light Vanilla Pearl. In Liquid Glass Enhanced on Android 12+, opening the login dialog applies full blur to the Steam activity behind it and restores the original content effect when dismissed.
- Steam Library's **Install** action downloads game depots into the app's private library. Adding a shortcut lets the user choose a Windows executable and container; that shortcut launches the executable directly with Wine inside the selected container, without requiring the official Steam desktop client. Steam account ownership and game DRM requirements still apply.
- Steam-created shortcuts also expose optional **Steam Launcher** and **Steam Offline Mode** settings. Launcher mode is accepted only when the chosen container already has the official Windows Steam client plus a valid installed `appmanifest_<appid>.acf` and game directory; otherwise launch stops with an explicit error. The app does not fabricate Steam manifests, install or sign in to the desktop client, or bridge the Android JavaSteam token into Wine. Direct JavaSteam depot downloads therefore do not automatically become Steam-client-managed installs, and the in-Wine client may require a separate sign-in. Offline mode additionally depends on that client having cached credentials. Legacy Steam emulation and runtime DRM-patching options are intentionally excluded.
- Steam reconnect now retries indefinitely with capped backoff, replaces a failed JavaSteam client instance after transport loss or connection timeout, and requests an immediate retry when Android reports a validated network recovery. A 10-second network check supplements Android callbacks so recovery does not depend on toggling mobile data.
- Design references: [GameNative](https://github.com/utkarshdalal/GameNative) and Bannerlator/Cmod. Runtime libraries: [JavaSteam](https://github.com/Longi94/JavaSteam) (MIT) and [ZXing](https://github.com/zxing/zxing) (Apache-2.0).
- Relevant code: `store/SteamStoreActivity.java`, `store/SteamRepository.java`, `store/SteamAuthManager.java`, `store/SteamQrAuthManager.java`, `store/SteamSessionStore.java`, `store/SteamDatabase.java`, `store/SteamDepotDownloadManager.java`, `store/SteamConnectionService.java`, `store/SteamNewsService.java`, `store/SteamNewsItem.java`, `store/SteamBadgeService.java`, `MainActivity.java`, `res/menu/main_menu.xml`, and `AndroidManifest.xml`.

### UI, navigation, and visibility

- Adds a continuously animated PlayStation-inspired wave-and-particle background, drawn frame-by-frame by a custom Android `View`; this is actual motion/shape animation, not a static image translation.
- Places the animated view behind the main navigation content so transparent fragment roots can reveal it.
- Provides seven global appearance choices: **Liquid Glass Enhanced** (the fresh-install default), **Midnight Navy**, **Neon Amethyst**, **Vanilla Pearl**, **Graphite Shadow**, **Ruby Flare**, and **Black AMOLED**. The six solid palettes use distinct surfaces and accents; Black AMOLED uses a true-black background with white contrast. The first app launch requires the user to select one in a non-dismissible picker; the same picker is available from Settings. Previously selected themes migrate to the closest matching new palette.
- Applies the selected palette to shared app surfaces, text, controls, dialogs, Steam screens, controller editors, the in-game drawer, the performance HUD, radial wheels, and the default touchscreen-control style. Keep shared drawables/styles and runtime theme application consistent; a change limited to the launcher screen is incomplete.
- Settings cards that have explicit legacy backgrounds are marked with the `settingsSurface` tag and receive a runtime themed surface; do not globally replace `bordered_panel_dark`, which is also used by unrelated screens. Reapply the shortcut-details panel surface from the current palette when the Shortcuts view is created/resumed.
- Controller-navigation hint chips and labels derive their colors from the active theme's accent/on-surface roles, and the hint bar uses a themed surface. Keep connected-controller visibility behavior while avoiding the old per-button fixed colors when porting.
- Theme-sensitive text and surfaces must cover orientation-specific layouts as well: the portrait Shortcut Details layout preserves its two-column placement while allowing long values to wrap, and the landscape resource remains independently maintained.
- Liquid Glass Enhanced enables the animated `GlassBackdrop`, translucent surfaces, and Android 12+ blur-behind effects. The six named palettes use their own opaque themed surfaces and disable glass-only effects. The Steam store panels and dialogs follow the selected theme instead of forcing glass surfaces.
- Liquid Glass Enhanced dialogs use native blur-behind when `WindowManager.isCrossWindowBlurEnabled()` reports it available; if the system disables cross-window blur, Android 12+ falls back to blurring the host activity content and restores it when the dialog closes. Custom spinner selectors, popup menus, and popup windows use app-side backdrop blur because those popup implementations do not request native dialog blur. Below Android 12, retain the drawable fallback; do not promise a live app-side blur.
- Android system permission sheets remain OS-owned and cannot be themed by the app. App-owned dialogs and popup surfaces use the selected palette, with native or adaptive app-side blur only in Liquid Glass Enhanced; below Android 12, retain the drawable fallback for glass surfaces.
- Distinguish true compositor blur from tinted surfaces: app dialogs and custom Spinner/popup implementations request or apply blur, while inline panels use themed drawables and are not themselves live backdrop blur.
- Preserve the separately tuned popup treatments (`liquid_glass_popup.xml`, `liquid_glass_menu.xml`, and `liquid_glass_dialog.xml`) for Liquid Glass Enhanced. Other themes use solid themed surfaces.
- Preserve the separately tuned popup treatments: dropdown (`liquid_glass_popup.xml`), card action menu (`liquid_glass_menu.xml`), and editor/dialog (`liquid_glass_dialog.xml` / `liquid_glass_editor_background.xml`). Do not homogenize their opacity; the three-dot card menu is intentionally stronger than edit dialogs.
- Uses translucent glass surfaces so the animated background remains visible through menus, while preserving readable text and touch feedback. Keep Liquid Glass surfaces light enough to avoid a dark/black veil over the backdrop.
- The in-game navigation drawer uses borderless rounded rows in every theme; its selected/ripple state is colored from the active palette.
- Spinner option rows use transparent backgrounds and no row dividers in Liquid Glass Enhanced. The custom spinner dialog is sized and capped using the visible window frame so long root governor/scheduler lists remain within the usable screen area.
- The theme-selection bottom sheet sizes its scroll region from the current visible window frame, allowing all theme choices to be reached across devices with different status/navigation bars and screen heights.
- The Containers screen retains the glass toolbar/title. Each card uses one rounded outer glass surface; do not add a second inset glass background behind its text, which appeared as a long purple strip.
- The Shortcuts **Add game** card uses one full-card glass surface in Liquid Glass Enhanced and is excluded from shortcut-carousel child blur; do not add a nested inset surface or blur layer.
- The File Manager's secondary toolbar (drive selector, path, and action buttons) uses the shared glass toolbar drawable instead of an opaque `windowBackground`.
- Shows controller-navigation hints only while a physical game controller is connected and centers the hint row; both the bar and its button/label colors follow the selected theme. Preserve the upstream input/control stack and this layout adjustment when porting.
- Virtual gamepad detection is based on whether any touchscreen-control binding maps to a gamepad button, including mixed keyboard/gamepad profiles; derive this from loaded bindings so edits take effect immediately.
- The fake evdev controller redirects `/dev/input` directory enumeration and access checks to its backing directory, reports event files as character devices, and sizes variable-length capability/name ioctls to the caller's request. These compatibility details help games that filter devices before opening them; this preload-based evdev path still cannot guarantee support for games that bypass it or require the legacy `/dev/input/js*` interface.
- Keeps Adrenotools GPU Drivers visible in the main navigation regardless of GPU brand.
- Adds an optional root-only CPU performance profile to the in-game Performance dialog. The profile and available governors unlock only after the user grants `su` access through their root manager; the selected governor is applied while a game runs and the previous per-policy governors are restored on pause/exit, with a saved recovery record for the next app launch.
- Removes the redundant standalone in-game Frame Generation menu entry while retaining the frame-generation controls inside Graphics Enhancements.
- Container discovery and shortcut loading share mutable state. `ContainerManager.getContainers()` returns a synchronized snapshot and `loadContainers()` is synchronized; keep callers iterating snapshots to avoid `ConcurrentModificationException` during background shortcut loading.

- Uses **Winlator Mali+** as the app label and adds/updates project and Bannerlator credit links in the About/release documentation.
- The configured product flavors keep the same visible app name and use these package IDs:
  - `standard`: `com.winlator.mali.plus`
  - `ludashi`: `com.ludasi.benchmark`
  - `antutu`: `com.antutu.ABenchMark`
  - `futuremark`: `com.futuremark.dmandroid.application`

## Upstream capabilities to preserve

These are part of upstream Winlator Mali 1.2 rather than unique Mali+ port additions, but they are easy to lose during a rebase and are required compatibility targets:

- Native EGL/Gladio rendering and its normal fallback path.
- ZeroFG frame generation and the upstream `zerofg` native build target.
- Upstream graphics enhancements, controller/input system, HUD, themes, SteamGridDB artwork/save management, Adrenotools driver management, and container configuration behavior.
- Existing built-in Vulkan wrapper variants and Mali-oriented BCn/cache options.

Do not describe these as new features of this port unless the newer upstream revision has dropped them and the port actually restores them.

## Rebase checklist for a newer upstream

1. Start from a clean checkout of the requested upstream release and record its commit. Keep the current integration branch/source available for comparison.
2. Port features by behavior and contracts, not by copying old classes. Inspect changes to `XServerView`, `XServer`, `Drawable`, `GPUImage`, renderer lifecycle, JNI signatures, and CMake targets.
3. Preserve both renderer paths: upstream EGL/Gladio + ZeroFG, and optional Vulkan + LSFG/Win-FG. Verify defaults remain safe and old container/shortcut configs still load.
4. Preserve settings migration/fallback behavior for renderer IDs, wrapper IDs, frame-generation values, and shortcut-to-container inheritance.
5. Port wrapper catalogue validation and extraction together with both Graphics Driver selectors. Test the full downloaded-wrapper selection → save → reopen → launch path.
6. Port the PanVK GitHub release catalog with live API fetch, repo-specific Adrenotools ZIP allowlists, progress/integrity checks, and validated import. Check that GitHub asset naming and Adrenotools `meta.json` contracts still match; do not broaden the list to arbitrary ZIPs or raw driver libraries. Test refresh after a new release, download, import, duplicate handling, and subsequent driver selection.
